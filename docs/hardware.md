# ผลวัดจากบอร์ดจริง

ทุกตัวเลขในไฟล์นี้ **วัดจากบอร์ดตัวนี้** ด้วย `firmware/probe/` ไม่ใช่ค่าจาก datasheet
และไม่ใช่เหตุผลเชิงออกแบบ — ที่นี่เก็บเฉพาะสิ่งที่โค้ดบอกไม่ได้ว่ามันมาจากไหน
เหตุผลว่าทำไมโค้ดถึงใช้ค่าเหล่านี้ อยู่ในคอมเมนต์ข้างค่านั้นเอง

ESP32-D0WD-V3 rev 3.1 · 4MB flash · ไม่มี PSRAM · พอร์ต `/dev/cu.usbserial-*`
MAC 2 ไบต์ท้ายคือชื่อที่บอร์ดใช้โฆษณาบน BLE

## จอ

```
MADCTL          0x28   = MV | BGR   -> แนวนอน 320x240 origin มุมบนซ้าย
ลำดับสี         BGR    ไม่ใช่ RGB
Inversion       ปิด    (INVOFF)
COLMOD          0x55   16 bit/pixel
```

**เลขรุ่นชิปพิสูจน์ไม่ได้ และไม่จำเป็นต้องพิสูจน์** — จอล็อกการอ่าน ID (`0x04`, `0xD3`,
`0xDA/DB/DC` คืนศูนย์) มีแต่ `0x0A` ที่ตอบ `0x98` ซึ่งเหมือนกันทั้ง ILI9341 และ ST7789
พฤติกรรมชี้ไป ILI9341 (inversion ต้องปิด ส่วน ST7789 เกือบทั้งหมดต้องเปิด)
**firmware ใช้ค่าคอนฟิกด้านบน ไม่ใช่เลขรุ่น**

## ขา

```
TFT (SPI2):   MOSI 13  MISO 12  SCLK 14  CS 15  DC 2  RST -1  BL 21   [ยืนยันแล้ว]
RGB LED:      R 4   G 16   B 17          (active low)                  [ยังไม่ได้ตรวจ]

microSD:      CS 5  MOSI 23  MISO 19  SCK 18                          [ไม่ใช้]
Speaker:      GPIO 26 (DAC1)                                          [v2]
```

## จอสัมผัส

**ชิปมีจริงและอ่านได้** · probe ชี้ทีละมุมบนจอแล้วเก็บ 32 ตัวอย่างต่อมุม ค่าที่จดคือมัธยฐาน
วงเล็บคือช่วงต่ำสุด-สูงสุดของนิ้วที่วางนิ่งอยู่กับที่ (คือ noise ของชิป ไม่ใช่การขยับนิ้ว):

```
มุม (พิกัดจอแนวนอน)    ADC x                ADC y
TL  ( 20, 20)          631  [ 456- 643]      436  [ 411- 464]
TR  (300, 20)          585  [ 502- 610]     3441  [3424-3454]
BL  ( 20,220)         3443  [3189-3515]      411  [ 356- 446]
BR  (300,220)         3439  [3420-3564]     3489  [3462-3503]

ตอนไม่แตะ   x = 0   y = 4095   z1 = 1-2      IRQ = 1
ตอนแตะ                         z1 = 260-1570 (ตามแรงกด)   IRQ = 0
```

**แกนของชิปสลับกับแกนของจอ**: `ADC y` คือแกนนอน (ซ้าย ~420 → ขวา ~3465) และ `ADC x`
คือแกนตั้ง (บน ~600 → ล่าง ~3440) ทั้งคู่เพิ่มค่าไปทางเดียวกับพิกัดจอ ไม่มีการกลับทิศ —
เพราะ XPT2046 ไม่รู้จัก MADCTL แกนของมันจึงเป็นแกนของแผงตอนตั้ง ส่วนแนวนอนเป็นผลของ
`MADCTL 0x28` ที่ตัวจอทำให้ทีหลัง **ใครเขียน swipe ต้องสลับแกนเอง**

ความชันที่วัดได้ (สองรอบแยกกัน): แนวนอน ~10.7-10.9 นับต่อพิกเซล · แนวตั้ง ~13.8-14.1
ส่วนแกนที่ไม่ควรขยับก็ไม่ขยับจริง — เลื่อนตามแนวนอน 280 px แล้ว `ADC x` เปลี่ยนแค่ -43
และเลื่อนตามแนวตั้ง 200 px แล้ว `ADC y` เปลี่ยนแค่ +7 คือสองแกนแยกกันสะอาด ไม่ต้องแก้เอียง

เลขพวกนี้พอบอกทิศและระยะของ swipe แต่ยังไม่ใช่ค่า calibrate ที่แม่นพอจะแปลงเป็นพิกเซล —
ทั้งสี่มุมวัดที่ระยะ 20px จากขอบ ขอบจริงจึงเป็นการคาดคะเนนอกช่วงที่วัด ไม่ใช่ค่าที่วัดมา

**ตัวชี้ขาดว่าชิปมีจริงคือค่า ADC ไม่ใช่ IRQ** — ถ้าไม่มีชิปหรือขาไม่ตรง MISO จะลอยและค่าจะนิ่ง
ที่ 0 หรือ 4095 ตลอดแม้ตอนแตะ · ที่นี่ตอนไม่แตะได้ `x=0 y=4095` ซึ่งหน้าตาเหมือนขาลอยเป๊ะ
แต่ z1 ขยับ 1-2 และค่าสี่มุมต่างกันชัดตอนแตะ · IRQ (GPIO 36) อ่านเป็นระดับได้จริง (1 ตอนว่าง
0 ตอนแตะ) แปลว่าบอร์ดมี pull-up ภายนอกให้ เพราะขา 36 เป็นอินพุตอย่างเดียวและไม่มี pull-up ภายใน

**อย่าวัดโดยปล่อยให้แตะอิสระแล้วค่อยเดาทีหลังว่าค่าไหนคือมุมไหน** — รอบแรกทำแบบนั้นแล้วจับคู่
มุมผิด จนสรุปว่า "แกน y กลับทาง" ซึ่งไม่จริง · probe จึงชี้ทีละมุมแล้วติดป้ายมุมมากับผลเลย

XPT2046 อยู่บน SPI3 คนละ host กับจอ (SPI2) — probe วาดจอไปด้วยขณะ polling สัมผัส
ที่ 20 Hz ทั้งสองบัสทำงานพร้อมกันได้โดยไม่ต้องล็อกอะไรร่วมกัน

## RAM

วัดตอนทำงานจริง (BLE + WiFi + LAN + mDNS + LVGL ขึ้นครบ อยู่บนทาง LAN สิบนาที):

```
idf.py size      DRAM static เหลือ 24060 · IRAM เหลือ 22105
esp_get_free_heap_size()          ~30 KB
esp_get_minimum_free_heap_size()  ~23 KB   <- ก้นจริง ถึงตอนนาทีที่ 3 แล้วไม่ลงอีก
```

**กรอบที่ต้องคิดคือ 23KB ไม่ใช่ 61KB ที่ `heap_init` โฆษณาตอนบูต** — WiFi กับ LAN จอง
หลังบรรทัดนั้น ตัวเลขตอนบูตจึงมองโลกในแง่ดีเกินจริงเกือบสามเท่า ของที่จองก้อนโตกว่านี้
ต้องวัดใหม่ ไม่ใช่เดาจาก `idf.py size` อย่างเดียว · `main.c` จึงพ่น `heap`/`min` นาทีละ
บรรทัดไว้ถาวร: ที่รั่วช้าๆ ไม่มีอาการอะไรเลยจนกว่าจะจองไม่ผ่านแล้วบอร์ดรีบูตทิ้ง
