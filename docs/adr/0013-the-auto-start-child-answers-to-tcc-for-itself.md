# ลูกของ auto-start รับผิดชอบสิทธิ์ของตัวเอง

`SessionStarter` เปิด session สั้นๆ ให้เองเมื่อหน้าต่างห้าชั่วโมงหมด โดย spawn `claude` เป็น
ลูกของแอป · ผลข้างเคียงที่ไม่มีใครตั้งใจคือ **กล่องขอสิทธิ์ของ macOS เด้งขึ้นมาในชื่อ
TamaClaude ทุกครั้งที่หน้าต่างรีเซ็ต** ทั้งที่แอปไม่ได้ขออะไรใหม่เลย

TCC ไม่ได้ถามในนามโปรเซสที่แตะของจริง มันถามในนาม *responsible process* ซึ่งปริยายคือ
บรรพบุรุษที่เป็นแอป · `tccd` พูดเรื่องนี้ตรงๆ:

```
AUTHREQ_ATTRIBUTION: responsible={com.tamaclaude.daemon, pid=14689},
                     accessing={com.anthropic.claude-code, pid=45708}
Failed to match existing code requirement for subject com.tamaclaude.daemon
AUTHREQ_PROMPTING: service=kTCCServiceSystemPolicyDocumentsFolder,
                   subject=Sub:{com.tamaclaude.daemon}
```

สองบรรทัดกลางคือเหตุที่มันไม่จบสักที: ลายเซ็นเป็น adhoc (`make-app.sh` เซ็นด้วย `--sign -`)
csreq ที่เก็บไว้ตอนผู้ใช้กดอนุญาตจึงไม่เคยตรงกับไบนารีปัจจุบัน คำตอบไม่ถูกจำ แล้วรอบหน้าก็ถามใหม่

เราจึงบอกให้ลูกรับผิดชอบตัวเองตอน spawn ผ่าน `responsibility_spawnattrs_setdisclaim`
(`Spawn.swift`) · กล่องสิทธิ์ที่ `claude` ทำให้เกิดจะขึ้นในชื่อของมันเอง ไม่ใช่ของแอป และ
ไม่ไปแตะ record ของ `com.tamaclaude.daemon` อีก

## ราคาที่จ่าย

`responsibility_spawnattrs_setdisclaim` ไม่มี header สาธารณะ ต้อง `dlsym` เอา — Apple
ถอดออกเมื่อไหร่ก็ได้ · เรารับได้เพราะความล้มเหลวของมันคือการถอยกลับไปที่พฤติกรรมเดิม
ไม่ใช่การพัง: หาสัญลักษณ์ไม่เจอก็ยัง spawn ต่อ แค่ log ไว้ (Chrome และ Electron เดินทางนี้
มาหลายปีด้วยเหตุผลเดียวกัน)

และมันบังคับให้เลิกใช้ `Process` — `Process` ไม่เปิดให้ตั้ง spawn attribute เลยสักตัว
ทุกอย่างที่มันแถมมาจึงต้องเขียนเอง: file actions, การเก็บศพลูก, สถานะขาออกที่ต้องอ่านเป็น
`128 + สัญญาณ` ให้ตรงกับเลขที่ `SessionProcess.classify` เคยเห็น

## ทางที่ไม่ได้เลือก

**เซ็นด้วยใบรับรองถาวรแทน adhoc** แก้เฉพาะครึ่งหลัง — คำตอบของผู้ใช้จะถูกจำ แต่กล่องยังเด้ง
ในชื่อ TamaClaude หนึ่งครั้งต่อสิทธิ์หนึ่งอย่างที่ `claude` ไปแตะ ซึ่งเป็นคำถามที่ผิดคน:
คนที่จะตอบว่า "ให้ claude อ่าน Documents ไหม" ไม่ควรถูกถามผ่านชื่อแอปที่วาดมาสคอต · สองอย่างนี้
แก้คนละครึ่ง ทำทั้งคู่ได้และควรทำ

**ยิงผ่าน `launchctl` หรือ `open`** ตัดสายบรรพบุรุษได้จริง แต่แลกกับการไม่มี pipe ให้อ่านว่า
ลูกตายเพราะอะไร ซึ่งเป็นสิ่งเดียวที่แยก "ยังไม่ login" ออกจาก "เน็ตสะดุด" — และการแยกนั้นคือ
เหตุผลทั้งหมดที่ `SessionStarter` ล็อกตัวเองเป็นบางกรณีเท่านั้น

**ตัดฟีเจอร์ auto-start ทิ้ง** เป็นทางที่ถูกถ้าปัญหาคือ "แอปเปิด session เอง" แต่ปัญหาจริงคือ
"ลูกยืมตัวตนของพ่อไปขอสิทธิ์" ซึ่งจะกลับมาทุกครั้งที่แอปนี้ spawn อะไรที่ไม่ใช่ตัวเอง
