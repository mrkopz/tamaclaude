# หนึ่งเฟรมต่อหนึ่ง page ไม่ขยาย Snapshot

ข้อมูลของ page ใหม่แต่ละหน้าเดินทางเป็น page frame ของตัวเอง มี page id + data age + payload
เฉพาะหน้านั้น board เก็บทับตาม id ส่วน `Snapshot` ของหน้ามาสคอตยังคงรูปเดิมทุกไบต์

ทางเลือกที่ปฏิเสธคือขยาย `Snapshot` ให้พกทุกหน้า ซึ่งชนเพดาน 500 ไบต์ทันที (ก้อนปัจจุบันต้องตัด
body ของ card ทิ้งอยู่แล้ว) และจะบังคับให้ต้องเขียน chunking บน BLE พร้อม reassembly กับ timeout
ทั้งชุด อีกทางที่ปฏิเสธคือทำ chunking ตรงๆ ซึ่งเป็นโค้ดที่ผิดพลาดง่ายที่สุดในระบบทั้งหมด

เหตุผลที่ชี้ขาดไม่ใช่แค่ขนาด แต่คือ**จังหวะ**: ราคาหุ้นขยับทุกนาที อากาศทุก 15 นาที ปฏิทินทุก 5 นาที
ถ้ารวมเป็นก้อนเดียว board จะถูกเขียนใหม่ทั้งก้อนทุกนาทีแม้ผู้ใช้กำลังดูหน้ามาสคอตอยู่ ซึ่งขัดกับกฎเดิม
ที่มีอยู่แล้วว่าห้ามยิง board ทุกวินาที

## ผลที่ตามมา

board มีข้อมูลไม่ครบทุกหน้าพร้อมกันได้เป็นเรื่องปกติ ไม่ใช่ความผิดพลาด และแต่ละหน้ามี data age
ของตัวเองแยกกัน
