# บอร์ดอ่านเฟรมของหน้าหนึ่งไปวาดอีกหน้าได้

ท้องฟ้าของหน้ามาสคอตรู้แค่ "กี่โมง" มาตั้งแต่ต้น: มันอ่าน `snapshot.clock` แล้วเลือกช่วงเวลา
วางดวงอาทิตย์/ดวงจันทร์บนส่วนโค้ง แล้ววาดเมฆลอยกับดาวกะพริบ · ตอนนี้มันรู้ "อากาศเป็นยังไง"
ด้วย — ฟ้าปิดเมื่อฟ้าปิด ฝนตกเมื่อฝนตก

**ข้อมูลนั้นไม่ได้เดินทางมาใหม่** มันอยู่บนบอร์ดอยู่แล้วในชื่อ `s_weather` ที่ `ct_pages.c`
แคชไว้ตั้งแต่ ADR-0002 และ ADR-0003 ให้หน้าอากาศใช้ · สิ่งที่ ADR นี้อนุญาตคือให้ *หน้าอื่น*
อ่านมันได้

## ทำไมไม่ส่งมาใหม่

ทางเลือกตรงไปตรงมากว่าคือเติมคีย์ลงใน `Snapshot` — `{"w":61}` ประมาณแปดไบต์ ซึ่งจะทำให้
กติกาเดิมยังจริงคำต่อคำ: daemon เป็นเจ้าของทุกการตัดสินใจเรื่องเนื้อหา บอร์ดวาดตามที่บอก

ที่ไม่เอาเพราะราคาไม่ได้อยู่ที่แปดไบต์ แต่อยู่ที่ **แปดไบต์ทุกวินาที ในงบ 500 ที่บีบอยู่แล้ว**
`Snapshot.encoded` ตัด body ของการ์ด ตัดหัวการ์ด ตัดการ์ดทั้งใบ แล้วตัดโควตาทิ้ง ตามลำดับนั้น
เพราะพื้นที่ไม่พอเป็นสภาพปกติ ไม่ใช่กรณีพิเศษ · เอาแปดไบต์ไปให้ค่าที่เปลี่ยนทุก 15 นาที
แลกกับความถี่ที่ถูกส่งซ้ำทุกวินาที คือการจ่ายผิดหน่วยเวลาสามระดับ

และมันจะเป็นสำเนาใบที่สองของค่าที่บอร์ดถืออยู่แล้ว ซึ่งเป็นความผิดพลาดชนิดที่โปรเจกต์นี้
เขียนกันไว้หลายที่ (`scene_phase` ในหน้าอากาศไม่ใส่เวลาลงเฟรมด้วยเหตุผลเดียวกันเป๊ะ:
"Mac ส่งเวลามาทุกวินาทีอยู่แล้ว ส่วนเฟรมอากาศมาทุก 15 นาที การใส่เวลาลงไปด้วยคือสำเนาที่
เก่ากว่าอีกใบ")

## บรรทัดฐานนี้มีอยู่แล้ว แค่กลับทิศ

หน้าอากาศอ่าน `clock` จาก snapshot ของหน้ามาสคอตมาตั้งแต่ ADR-0009 — ฉากของมันเลือกช่วงเวลา
จากนาฬิกาที่ไม่ได้อยู่ในเฟรมของตัวเอง · ADR นี้แค่บอกว่าทิศกลับก็ทำได้ และเขียนกติกาให้ชัด:

**บอร์ดอ่านเฟรมของหน้าอื่นได้ แต่ต้องไม่ *ตัดสิน* อะไรที่ daemon ตัดสินไปแล้ว** — สิ่งที่วาด
ต้องเป็นค่าที่ daemon ส่งมาตรงๆ (รหัส WMO ตัวเดิม แปลด้วยตารางเดียวกับที่หน้าอากาศใช้)
ไม่ใช่ค่าที่บอร์ดสังเคราะห์ขึ้นเอง · เส้นแบ่งเดิมของ ADR-0002 ไม่ขยับ: daemon เป็นเจ้าของ
*เนื้อหา* บอร์ดเป็นเจ้าของ *ว่าอะไรอยู่บนจอตอนนี้* — และ "ฟ้าของหน้ามาสคอตวาดอะไร"
อยู่ฝั่งหลัง

## ผลที่ตามมาสามอย่างที่ต้องเขียนไว้

**หนึ่ง — คำศัพท์ที่ใช้ร่วมต้องย้ายบ้าน** `bucket()` (รหัส WMO → หกกลุ่ม) เคยอยู่ใน
`ct_weather_ui.c` ↔ `gen/weather.py` ตอนนี้อยู่ที่ `ct_sky.h` ↔ `gen/sky.py` ซึ่งเป็นที่ที่
`phase_at` ย้ายไปอยู่ด้วยเหตุผลเดียวกันเมื่อหน้าปฏิทินต้องใช้ · สำเนาสองใบจะเลื่อนจากกันเงียบๆ
แล้ววันหนึ่งรหัส 61 ก็เป็นฝนบนหน้าหนึ่งและเป็นเมฆบนอีกหน้า ทั้งที่ผู้ใช้ปัดสลับกันดูอยู่
· ฝั่ง Python ทิศ import ก็บังคับทางนี้ทางเดียวอยู่แล้ว: `weather.py` import `sky.py`
ทางกลับเป็นวงกลม

**สอง — เฟรมเก่าไม่ใช่เฟรม** หน้าอากาศพิมพ์อายุข้อมูลไว้ที่มุมจอ เฟรมที่ค้างอยู่จึงยังพูดความจริง
ได้ว่ามันค้าง · หน้ามาสคอตไม่มีที่ให้พิมพ์แบบนั้นเลย ฝนที่หยุดไปสามชั่วโมงแล้วจึงเป็นคำโกหก
ที่ไม่มีอะไรถ่วง — เฟรมที่เกิน `ct_weather_is_stale` (2.5 ชม.) ถูกปฏิบัติเหมือนไม่มีเฟรม
และฟ้าถอยกลับไปเป็นฟ้าตามเวลาล้วน ซึ่งเป็นฟ้าที่หน้านี้มีมาตลอด · หน้าที่ผู้ใช้ปิด
(`{"g":1,"x":1}`) ก็ทางเดียวกัน

**สาม — ผู้ตัดสินคือผู้ที่ถือนาฬิกา** การตัดสินว่าเฟรมยังใช้ได้ไหมอยู่ที่ `ct_pages.c`
ซึ่งเดินอายุของทุกหน้าอยู่แล้ว แล้วมันป้อนผลเข้า `ct_ui_set_weather(code, valid)` · ทางเลือก
ตรงข้าม (ให้ `ct_ui.c` อ่าน `s_weather` เอง) แปลว่าหน้ามาสคอตต้องรู้จักทะเบียนหน้า
ซึ่งตอนนี้มันไม่รู้ และการไม่รู้นั้นคือสิ่งเดียวที่กันไม่ให้ทุกหน้าพันกันหมด

## สิ่งที่ ADR นี้ไม่ได้อนุญาต

- **ไม่ได้อนุญาตให้บอร์ดคำนวณเนื้อหาใหม่จากเฟรมที่มี** เช่น เดาอากาศพรุ่งนี้จากแถวพยากรณ์
  หรือแปลงหน่วยเอง — สิ่งที่วาดได้คือสิ่งที่ daemon ส่งมา
- **ไม่ได้อนุญาตให้หน้าหนึ่งพังเพราะอีกหน้า** ไม่มีเฟรม = ฟ้าแบบเดิม ไม่ใช่หน้าเปล่า
- **ไม่ได้อนุญาตให้เรขาคณิตใช้ร่วมกัน** `[sky]` กับ `[weather]` มีตาราง deck/rain/snow/fog/bolt
  คนละชุด เพราะเส้นขอบฟ้าคนละเส้น (120 กับ 148) — ตารางที่จูนกับเส้นหนึ่งอ่านผิดที่อีกเส้น
  สิ่งที่ใช้ร่วมกันได้มีแค่ *ความหมาย* (กลุ่มอากาศ, สี) ไม่ใช่ *พิกัด*
