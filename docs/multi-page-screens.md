# หลายหน้าจอ — หุ้น คริปโต อากาศ ปฏิทิน

บันทึกผลการออกแบบก่อนลงมือ ยังไม่มีโค้ดใดถูกเขียน เอกสารนี้เป็นข้อตกลงว่าจะสร้างอะไรและด้วย
เหตุผลใด — คำที่ใช้เป็นไปตาม `CONTEXT.md` ส่วนการตัดสินใจที่ย้อนยากแยกไปอยู่ใน `docs/adr/`
0001–0007 เมื่อสิ่งนี้ถูกสร้างจริงแล้ว สาระที่ยังเป็นจริงต้องย้ายเข้า `DESIGN.md` และเอกสารนี้ถูกลบ

## รูปร่างที่ตกลงกัน

จอมี 5 page: **มาสคอต** (ของเดิม ไม่ถูกแตะ), **หุ้น**, **คริปโต**, **อากาศ**, **ปฏิทิน**
ผู้ใช้เปลี่ยนหน้าด้วยการ swipe ซ้าย/ขวา หรือปล่อยให้ page rotation เปลี่ยนเอง ตั้งค่าทุกอย่าง
ในแอปบน Mac

- ข้อมูลทุกอย่างดึงโดย Mac — board ไม่ต่ออินเทอร์เน็ตเลย (ADR-0001)
- board เก็บทุก page ไว้ใน RAM จึง swipe ได้ทันทีและยังดูย้อนได้ตอนขาดการเชื่อมต่อ (ADR-0002)
- แต่ละ page เดินทางเป็น page frame ของตัวเอง `Snapshot` เดิมไม่ถูกแก้ (ADR-0003)
- `PageKind` เป็น enum ปิด — board วาดเอง Mac ส่งแต่ข้อมูล (ADR-0004)
- ปฏิทินผ่าน EventKit ไม่ถือ credential ของ Google (ADR-0005)
- board ประกาศ PageKind ที่รองรับตอนเชื่อมต่อ (ADR-0006)
- touch รับเฉพาะ swipe แนวนอน ค่าคงที่มาจากการวัดด้วย probe (ADR-0007)
- ภาษาไทยถูกประกอบร่างบน Mac firmware แค่วาด glyph ที่เลือกมาแล้ว (ADR-0008)

## พฤติกรรมบนจอ

**มาสคอตจิ๋วอยู่ทุกหน้า** ย่อประมาณหนึ่งในสามไปมุมขวาบน ไม่มีท้องฟ้า ไม่มี prop ไม่มีชื่อโปรเจกต์
เหลือแค่ pose ปัจจุบัน และยังเคารพอายุขั้นต่ำ 5 วินาทีของ pose เหมือนเดิม เหตุผลที่ไม่ใช้จุดสีแทน:
มาสคอตที่หลับอยู่แปลว่า "ไม่มี session" ส่วนมาสคอตที่หายไปเลยแปลว่า "จอหลุดจาก Mac" — ความ
ต่างนี้ต้องแยกออกได้ ไม่งั้นจอเงียบสองแบบดูเหมือนกัน (หลักเดียวกับ `unknown ≠ zero`)

ต้นทุน: `ct_rects_scale_from()` มีอยู่แล้วและมาสคอตอยู่ในพิกัด unit อยู่แล้ว การย่อจึงแทบไม่มีต้นทุน
ไม่ต้องวาดอาร์ตใหม่

**ทุกหน้าแสดง data age เสมอ** เป็นบรรทัดเล็ก ไม่ใช่ "แสดงเมื่อเก่าเกินเกณฑ์" เพราะเกณฑ์เดียวใช้กับ
ทุกหน้าไม่ได้ — อากาศเก่า 40 นาทีคือปกติ หุ้นเก่า 40 นาทีตอนตลาดเปิดคือพัง เวลาดิบให้ผู้ใช้ตีความ
เองได้ถูกเสมอ ถ้าเกิน 10 เท่าของรอบดึงให้ขึ้นคำว่า stale ตรงๆ เพิ่มด้วย เพราะคนเหลือบจอไม่ได้อ่าน
ตัวเลขเล็ก page frame พก data age มาเป็นวินาที แล้ว board นับต่อเอง — กลไกเดียวกับ
`UsageSnap.remaining` ที่ส่งเวลาคงเหลือแทนเวลาสัมบูรณ์เพื่อให้เดินต่อได้ตอนสายหลุด

**page ที่ยังไม่เคยได้ข้อมูล** ต้องมีหน้าตาของมันเอง ห้ามเป็นจอเปล่าหรือโครงว่าง

**page ที่ผู้ใช้ปิด** หายจากรอบ swipe และรอบ rotation ไปเลย ไม่ใช่ swipe ไปเจอหน้าที่เขียนว่า
"ปิดอยู่"

## page rotation กับ swipe

board เป็นคนจับเวลา ไม่ใช่ Mac — ถ้า Mac สั่งเปลี่ยนหน้า Mac หลับก็เท่ากับจอค้างหน้าเดียวทั้งคืน
Mac ส่งแค่ค่าตั้ง (เปิด/ปิด, กี่วินาที, หน้าไหนอยู่ในรอบ)

หลัง swipe ให้เข้าสู่ **manual hold** — rotation หยุด 5 นาทีแล้วกลับเข้ารอบที่หน้าถัดไป ไม่ใช่
กลับหน้ามาสคอต การเปลี่ยนหน้าใส่คนที่กำลังอ่านคือพฤติกรรมที่แย่ที่สุด ส่วนการปักหมุดถาวรทำให้
ของที่ควรหมุนกลายเป็นค้างโดยผู้ใช้ไม่รู้ตัว

## attention jump

เมื่อมี session เข้าสถานะที่ต้องการคน (`waiting` / `alert`) board สลับไปหน้ามาสคอตเอง
**ครั้งเดียวต่อหนึ่งเหตุการณ์** — dedup ด้วย id ของเหตุการณ์ ไม่ใช่ด้วยสถานะที่ยังค้างอยู่ ไม่งั้น
ระหว่างที่ Claude รออนุญาต 10 นาที จอจะกระชากกลับทุกไม่กี่วินาทีจนใช้อะไรไม่ได้

ถ้าผู้ใช้ swipe หนีหลังการเด้ง สัญญาณต้องไม่หายไปเฉยๆ — มาสคอตจิ๋วมุมจอยังคงแสดง pose ที่รออยู่
บนทุกหน้า (หลักเดียวกับ `cardOverflow`: การเตือนที่หายเงียบๆ คือการเตือนที่หายไป)

เปิด/ปิดพฤติกรรมนี้ได้ในแอป

## แหล่งข้อมูลและรอบดึง

| page | แหล่ง | key | รอบดึง |
|---|---|---|---|
| หุ้น | Finnhub แผนฟรี (60 คำขอ/นาที) | ผู้ใช้ใส่เอง | 60 วิ **เฉพาะตอนตลาดเปิด** |
| คริปโต | CoinGecko | ไม่ต้องมี | 60 วิ ตลอดเวลา |
| อากาศ | Open-Meteo | ไม่ต้องมี | 15 นาที |
| ปฏิทิน | EventKit | ไม่มี (TCC) | 5 นาที |

ข้อจำกัดของ Finnhub ที่กำหนดรูปร่างดีไซน์:

- `/quote` คืนค่าทีละหนึ่งสัญลักษณ์ → watchlist 5 ตัว = 5 คำขอต่อรอบ จึง **บังคับเพดาน 5 ตัวต่อ
  page ในแอป** ไม่ปล่อยให้ผู้ใช้ใส่ 50 ตัวแล้วโดนจำกัดอัตรา เพดานนี้ทำให้งบ API เป็นค่าคงที่ที่
  คำนวณล่วงหน้าได้ และทำให้เฟรม 500 ไบต์พอแน่นอน (5 แถว × สัญลักษณ์+ราคา+% ≈ 200 ไบต์)
- แผนฟรีครอบคลุม **หุ้นสหรัฐเท่านั้น** — SET/หุ้นไทยอยู่นอกขอบเขตรอบนี้โดยรู้ตัว การเพิ่มทีหลัง
  ไม่ต้องแฟลชบอร์ด เพราะแหล่งข้อมูลอยู่ฝั่ง Mac ล้วนๆ (ADR-0004)

Finnhub key เก็บแบบเดียวกับ `sessionKey` เป๊ะๆ: ไฟล์ใน `~/.tamaclaude/` โหมด 600 ไม่ผ่าน argv
ไม่ผ่าน env ไม่ลง log ใช้ `SessionKeyFile.swift` เป็นแม่แบบ

ปฏิเสธการยิง endpoint ที่ไม่เป็นทางการ (เช่นของ Yahoo): มันเทาถึงผิดข้อกำหนดเมื่อแจกในโปรเจกต์
สาธารณะ และหน้าหุ้นที่พังเงียบๆ แล้วโชว์ราคาค้างของเมื่อวานคือของที่แย่กว่าไม่มีหน้าหุ้น

## การตั้งค่าบน Mac

ทุกค่าอยู่ใน `UserDefaults` และ **แอปเป็นบรรณาธิการเดียว** ไม่มีไฟล์ให้แก้มือ — ต่างจาก
`~/.tamaclaude/tools.json` ตรงที่อันนั้นเป็น override ที่ไม่มี GUI ให้แก้ จึงไม่มีทางขัดกัน แต่ค่าตั้ง
ของ page มี GUI เต็มรูปแบบ การมีสองแหล่งจะทำให้หน้าต่างโชว์ AAPL ขณะที่ระบบใช้ TSLA
`PreferencesWindowController` ยังไม่รู้จักที่เก็บข้อมูลเหมือนเดิม — ทุกอย่างเข้าออกผ่าน closure

ค่าที่ตั้งได้: หน้าไหนเปิด/ปิด · ลำดับหน้า · เปิด/ปิด rotation และรอบ (ตั้งต้น 20 วินาที) · ระยะ
manual hold (ตั้งต้น 5 นาที) · เปิด/ปิด attention jump · watchlist หุ้นและคริปโต (สูงสุด 5) ·
Finnhub key · ตำแหน่งอากาศและหน่วย · ปฏิทินที่จะแสดง

ตำแหน่งอากาศให้ผู้ใช้เลือกจากชื่อเมือง **ไม่ใช้ CoreLocation** — เลี่ยง TCC อีกใบ และของตั้งโต๊ะ
ไม่ได้ย้ายที่

หน้าปฏิทินแสดงนัดถัดไป 4 รายการภายใน 7 วัน

## ภาษาไทยบนจอ

ปฏิทินของผู้ใช้เป็นภาษาไทยเกือบทั้งหมด งานฟอนต์ไทยจึงไม่ใช่ของเสริม — **หน้าปฏิทินไม่มีความหมาย
ถ้าไม่มีมัน** และถูกยกขึ้นมาเป็นส่วนหนึ่งของขั้นที่ 5 เหตุผลเชิงสถาปัตยกรรมอยู่ใน ADR-0008 ส่วนที่นี่
คือสิ่งที่ต้องทำจริง

- ฟอนต์ OFL (Noto Sans Thai หรือ Sarabun) → LVGL font converter เอาเฉพาะ subset ที่ใช้ ที่ 12px
  และ 14px รวมทั้ง glyph variant ของสระบนและวรรณยุกต์ที่ระดับความสูงต่างกัน
- `tools/thai.toml` เก็บตารางว่าพยัญชนะตัวไหนหางสูง และ variant ไหนใช้เมื่อมีสระบนอยู่แล้ว
  แล้ว generate เป็นตารางทั้งฝั่ง Swift และ Python — แหล่งความจริงเดียว เหมือน `layout.toml`
- อัลกอริทึมเดินคลัสเตอร์พอร์ตสองฝั่ง (Swift สำหรับ daemon, Python สำหรับ `preview.py`)
  ต้องมีเทสต์ใน `tamatest` กันดริฟต์
- `Text.sanitize` เลิกทิ้งอักขระไทย แต่ยังทิ้งอย่างอื่นเหมือนเดิม
- **การนับความยาวข้ามอักขระที่กว้างศูนย์** (หมวด Mn) — สระบนและวรรณยุกต์ไม่กินความกว้าง
  การนับตัวอักษรตรงๆ ตัดข้อความไทยสั้นเกินจริงได้ราว 40% ซึ่งคือการตัดคำที่ใส่ได้ทิ้งโดยไม่มีใครรู้
  ไม่ยกระดับไปวัดเป็นพิกเซลจริงในรอบนี้ — `Limit.*` ทุกวันนี้ก็เป็นค่าประมาณกับฟอนต์สัดส่วนอยู่แล้ว
  การทำตารางความกว้าง glyph เป็นงานคนละชิ้น ไม่ควรพ่วงมา
- `Limit.*` ที่ตั้งไว้สำหรับ Montserrat ใช้กับฟอนต์ไทยไม่ได้ ต้องวัดใหม่สำหรับหน้าปฏิทิน — วัดใน
  `preview.py` ได้ เพราะมันใช้ฟอนต์บิตแมปตัวเดียวกับบอร์ดแล้ว
- ไทยกิน 3 ไบต์ต่อตัวใน UTF-8 (ชื่อนัด 20 ตัว = 60 ไบต์ · สี่รายการ ≈ 240 ไบต์ในงบ 500)
  **ไม่ประดิษฐ์การเข้ารหัสไบต์เดียวเอง** — `encoded()` วัดไบต์จริงและบีบเองอยู่แล้ว ส่วน base64
  จะกินคืนหนึ่งในสามแลกกับเฟรมที่อ่านไม่ออก

## ลำดับส่งของ

1. **probe touch** — โปรเจกต์ใน `firmware/probe/` อ่านค่า XPT2046 ดิบที่สี่มุม ตอบคำถามเดียวว่า
   ชิปมีอยู่จริงและอ่านได้ไหม จดผลลง `DESIGN.md` แล้วหยุด ยังไม่ทำ swipe
2. **โครงหลายหน้า + หน้าอากาศ** — Open-Meteo ไม่ต้องมี key ไม่ต้องมี TCC จึงพิสูจน์ท่อทั้งเส้น
   (page frame แยกหน้า, cache บน board, มาสคอตจิ๋ว, data age, capability, rotation) โดยไม่มี
   ตัวแปรอื่นปน
3. **หน้าคริปโต** — ท่อเดิม เพิ่ม PageKind
4. **หน้าหุ้น** — บวก UI ใส่ key และไฟล์โหมด 600
5. **หน้าปฏิทิน + ฟอนต์ไทย** — บวก EventKit, TCC และงานฟอนต์ทั้งชุด ทำคู่กันเพราะหน้าปฏิทิน
   ที่อ่านภาษาไทยไม่ได้คือหน้าที่ไม่มีประโยชน์สำหรับผู้ใช้คนนี้
6. **swipe** — ใส่ทับระบบที่ใช้งานได้อยู่แล้ว

ลำดับนี้จงใจให้ touch ซึ่งเป็นความเสี่ยงฮาร์ดแวร์ที่ประเมินไม่ได้จนกว่าจะจับจริง ไม่ขวางของที่ใช้งานได้

## ความเสี่ยงที่ยังไม่แก้

- **ตำแหน่งวรรณยุกต์ที่ยังไม่มีใครเห็นของจริง** — วิธีเลือก glyph variant พิสูจน์บนกระดาษได้
  แต่ความสวยจริงบนจอ 12px ยังไม่มีใครยืนยัน ขั้นที่ 5 ต้องเผื่อเวลาปรับตารางใน `tools/thai.toml`
  หลังเห็นของจริง — และเห็นได้จาก `preview.py` ไม่ต้องแฟลช
- **XPT2046 ทำเครื่องหมาย `[v2]`** — บอร์ดบางรุ่นย่อยอาจไม่มีชิปนี้ ขั้นที่ 1 มีไว้เพื่อรู้ให้เร็ว
- **Mac หลับ = ทุกตัวเลขแช่แข็ง** — บรรเทาด้วย data age ที่แสดงเสมอ ไม่ได้แก้
- **ค่า calibrate มาจากบอร์ดเครื่องเดียว** — จอของผู้ใช้คนอื่นอาจให้ค่าต่างไป ระยะ swipe แบบหยาบ
  ทนได้ระดับหนึ่ง แต่ยังไม่มีใครยืนยันข้ามเครื่อง
